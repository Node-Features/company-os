| Finding | Evidence | Notes |

| ~~Governance-autonomy drift~~ **RESOLVED 2026-08-24** | Was: [`architecture/governance.md:74`](../architecture/governance.md) said `knowledge.approve` was `human_only`; [`governance/policy.go:91`](../../apps/companyd/internal/governance/policy.go) used `AutonomyApprovalRequired`. Same root cause as `AutonomyHumanOnly` being dead code ([`findings.md`](findings.md) §2). | [`docs/adr/ADR-0010-authority-model-formalization.md`](../adr/ADR-0010-authority-model-formalization.md) resolved this explicitly: split into `knowledge.review.request` (still `approval_required`, requestable by anyone) and a generic, structural human-decider check in `ResolveApproval` (not a per-action `human_only` classification). `AutonomyHumanOnly` is now real — `governance.Request.RequestingPrincipalKind` exists and `Evaluate` checks it. See [`fixed-authority-model-formalization.md`](fixed-authority-model-formalization.md). |
| ~~Separation-of-duties is opt-in, not structural~~ **RESOLVED 2026-08-24** | Was: `ExcludedPrincipalID`/`ResourceOwnerPrincipalID` are per-use-case fields on `governance.Request`; `ProposeObjective`'s REQUIRE_APPROVAL set neither ([`objective_governance.go`](../../apps/companyd/internal/application/objective_governance.go)). | `docs/adr/ADR-0010-authority-model-formalization.md` moved self-approval enforcement out of per-use-case `governance.Request` fields entirely, into `ResolveApproval`'s unconditional decider check (`ports.ErrSelfApproval`) — every `CommandType`'s decide act is now protected, including Objective's, without touching `objective_governance.go`. Still masked from being *exploitable* today by [`gap-approval-principal-attribution.md`](gap-approval-principal-attribution.md)'s fixture-decider gap, which remains open — but the check itself is now real, structural code, not absent. |
| Knowledge reject skips governance re-evaluation | `rejectApproveKnowledgeItem` is a real `DRAFT`→`REJECTED` transition ([`knowledge_review.go:127-138`](../../apps/companyd/internal/application/knowledge_review.go)) that reuses the *original* pre-approval `GovernanceDecisionID` rather than re-evaluating; every other `CommandType`'s reject is a pure no-op (`default:` case, [`approval_resolve.go:53-55`](../../apps/companyd/internal/application/approval_resolve.go)). | Inconsistent, not currently known-exploitable; document the intended semantics (is reject-as-real-transition the right model, and should it re-check governance?) before adding a fourth resumable `CommandType`. |
| `RunEvaluation` non-transactional two-step write | `CreateEvaluation` then `UpsertPerformanceProfile` as separate calls ([`me_evaluation.go:57-71`](../../apps/companyd/internal/application/me_evaluation.go)); no compensating action if the second fails. | Low blast radius (internal M&E metrics, not authoritative Workflow state), but same class of gap as the approval-flow durability issue at smaller scale. |
| Cross-department reads are not snapshot-isolated | `RunResourceEvaluation` reads Finance+M&E across three unsynchronized calls ([`finance_evaluation.go:24-100`](../../apps/companyd/internal/application/finance_evaluation.go)); `ProposeObjective`/`CaptureKnowledgeCandidate` similarly. | Documented as acceptable by the code's own comments today; worth a real design decision once a second concurrent writer per subject becomes plausible. |
| `ScheduleRetry` has no status guard | Plain `UPDATE ... WHERE organization_id=$2 AND intent_id=$3`, no `WHERE status=...` ([`execution_repo.go:151-154`](../../apps/companyd/internal/adapters/persistence/supabase/execution_repo.go)). | No known trigger path today; add the guard opportunistically when [`gap-execution-lease-reclaim.md`](gap-execution-lease-reclaim.md) is implemented, since that work touches the same file and the same state machine. |
| Migration hygiene | `cmd/migrate` replays every `*.sql` file with no applied-migrations tracking (doc comment: "safe to re-run only against a fresh database"); several one-off manual-apply tools were created and deleted per slice. | Fine for single-operator dev; becomes a real problem the moment a second contributor or CI (see [`gap-ci-integration-coverage.md`](gap-ci-integration-coverage.md)) needs to apply migrations against a non-fresh database. Needs a `schema_migrations`-tracking mechanism before either happens. |
| Multi-tenant isolation is structural-only-by-absence | Every use case scopes to one hardcoded `fixtures.OrganizationID`; no enforcement code exists, just no second tenant. Self-flagged in [`security/workspace-isolation.md:27`](../security/workspace-isolation.md). | **Do not create a second Organization before real org-scoping enforcement exists** — see [`findings.md`](findings.md) §3 row 12 (P0 if triggered). Otherwise no action needed today. |
| Execution-lease CAS returns plain error, not `ports.ErrConflict` | `RecordDispatched`/`RecordTerminal`'s zero-rows-affected case ([`execution_repo.go:132-135,145-148`](../../apps/companyd/internal/adapters/persistence/supabase/execution_repo.go)) uses `errors.New(...)` instead of the codebase's usual `ports.ErrConflict`. | Small consistency fix; bundle with [`gap-execution-lease-reclaim.md`](gap-execution-lease-reclaim.md) since it touches the same file/methods. |
