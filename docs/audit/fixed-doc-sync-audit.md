# Fixed: Documentation Synchronization Audit

Status: IMPLEMENTED (2026-08-24) — findings verified against code/tests/migrations first, documentation then updated to match; a lightweight automated check now guards the two most mechanical classes of drift found. **Not yet committed to git** as of this writing — check `git status` before assuming this is landed on a branch.

Project-owner-directed, not triggered by a `gap-*.md`. Scope: cross-check documentation claims (`README.md`, `ARCHITECTURE.md`, `CONTRIBUTING.md`, `SECURITY.md`, `ROADMAP.md`, all 10 ADRs, all 20 `docs/domain/*.md`, all 18 `docs/architecture/*.md`, every index `README.md`) against actual implementation state (Go code, tests, HTTP routes, migrations), per this repo's own "determine actual state from code first, then update documentation to match reality" instruction — not the reverse.

## Method

Two parallel read-only research passes (mirroring `findings.md`'s own six-parallel-investigation method, scaled to this narrower scope): one over top-level docs + all ADRs + index files, one over the seven doc-only domain-package stubs + `supabase/migrations/`. Cross-checked against `docs/audit/findings.md`/`backlog-p2-p4.md` (the existing evidence base) so nothing already tracked there was re-reported as new. `.claude/worktrees/` (a stale isolated git-worktree snapshot from an unrelated prior agent run) was excluded from scope — it is not canonical repo content.

## Contradictions considered and deliberately *not* fixed

Per this task's own instruction not to rewrite documentation merely to look clean, and because some of these are explicitly reserved for the project owner's judgment, not a documentation-accuracy fix:

- **`ADR-0005` remains `Status: PROPOSED`** — unlike `ADR-0006`/`ADR-0007` (row 6, approved this session once the project owner reviewed and signed off), `ADR-0005`'s own acceptance checklist has two substantive prerequisites beyond sign-off that have not happened: reconciling `internal/kernel/organization`/`objective`/`capability`'s illustrative signatures against their domain docs' actual legal-transition tables, and porting `docs/domain/department.md`'s lifecycle into real `internal/domain/department` Go types (which would itself immediately re-open row 7's `department` "doc-only stub" finding if done carelessly). Flipping `Status` without that work would recreate exactly the class of contradiction this audit exists to fix — left `PROPOSED`, with its real prerequisites named in `backlog-p2-p4.md`, not rubber-stamped.
- **`ADR-0002`/`ADR-0003`**: both `APPROVED` design decisions with narrower or zero implementation so far (`ADR-0002`'s `DepartmentRegistry` isn't built; `ADR-0003`'s full `IntelligenceRouter`/`ModelProfile` routing is narrower `fallback` package today). Not a contradiction — both ADRs' own text already scopes "which concrete implementation proves this" as open future work, the same pattern `ADR-0004`'s sub-questions used successfully. No edit needed.
- **`docs/reference-implementations/README.md` vs. `docs/references/README.md`** — a pre-existing, already-tracked `OPEN QUESTION` (`current-state.md`, `backlog-p2-p4.md` P3) about two directories that look like predecessor/successor. Re-confirmed still present and unresolved during this audit, not newly found. Deciding which one should remain is a project-owner call this audit does not make for them.
- **13 tables** (`domain_events`, `event_outbox`, `idempotency_keys`, `principal_organization_bindings`, `signals`, `research_questions`, `findings`, `recommendations`, `budgets`, `cost_constraints`, `price_profiles`, `resource_usage`, `resource_evaluations`) have a real migration and are mentioned in `ROADMAP.md` prose or a `docs/departments/*.md` file, but have no dedicated `docs/domain/*.md` page of their own. Not a contradiction (nothing claims otherwise), and creating 13 new domain documents to close a coverage gap would be exactly the "giant documentation framework" this task's own instructions said not to build. Named here so it isn't rediscovered as new later.
- **`docs/domain/README.md`'s `Status` column** intentionally tracks document-review status, not Go-implementation status (the file says so explicitly: "Rows marked `NOT YET SPECIFIED` are planned contracts and may not have a file yet"). Confirmed working as designed, not a bug — this is exactly the ambiguity row 2's and row 7's fixes address by adding an explicit implementation caveat elsewhere instead of overloading this column's meaning.

## Automated consistency check

`scripts/check-docs-sync.sh` (new), wired into CI as a new step in the existing `go-fast` job (`.github/workflows/ci.yml`) — no new job, no database, adds seconds to an already-fast job. Deliberately small (~70 lines, no new dependency): three checks, chosen because they're the two most mechanical classes of drift this audit actually found (rows 6/7 above) plus one structural one that would have caught rows 3/etc. if it had existed sooner:

1. Every `docs/adr/ADR-*.md` has a recognized `Status:` value (`PROPOSED`/`APPROVED`/`REJECTED`/`SUPERSEDED`).
2. Every `docs/audit/*.md` file (except `README.md` itself) is referenced from `docs/audit/README.md`'s index table.
3. Every `docs/domain/*.md` claiming `Status: APPROVED` has real Go types in its corresponding `internal/domain/<name>` package — **unless** it's in the script's own `KNOWN_STUB_DOMAINS` allowlist (currently the same seven this audit found: `artifact department evaluation evidence metric resource workspace`). A companion check inverts this: if a listed stub package ever gains real types, the script fails until it's removed from the allowlist — so the allowlist can't silently go stale in either direction.

What this does **not** attempt to automate, deliberately, per this task's own "prefer lightweight... where practical" instruction rather than building a general framework: `docs/architecture/README.md`'s index completeness (row 3's class — would need a generic "every file in directory X is referenced in index Y" rule per index, more machinery than three known index files justify today); ADR-status-vs.-implementation drift (row 6's class — "is this ADR's decision actually shipped" isn't mechanically checkable without a fragile natural-language heuristic); README/CONTRIBUTING/SECURITY prose accuracy (rows 1/4/5 — inherently a human-judgment check). These remain manual, same as they were before this audit — named explicitly here so a future session doesn't assume they're covered.

Verified: `bash scripts/check-docs-sync.sh` passes clean against the repository after every fix in this document; a synthetic-fixture smoke test (temp directory, not the real repo) confirmed all three checks actually fail on a deliberately broken input (bad ADR status, an unindexed audit doc, an unlisted stub domain) before being confirmed clean again — the script is not a no-op.
