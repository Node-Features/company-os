# Fixed: Observability Model (Structured Logging, Correlation Identity, Metrics)

Status: IMPLEMENTED (2026-08-24) — implemented and verified against the real database. **Not yet committed to git** as of this writing — check `git status` before assuming this is landed on a branch.

This is the implementation record for [`docs/architecture/observability.md`](../architecture/observability.md), the authoritative design record — read it first. This document is the "what actually shipped, what it proves, what's still open" record, in the same shape as [`fixed-execution-lifecycle-hardening.md`](fixed-execution-lifecycle-hardening.md), [`fixed-runtime-resilience.md`](fixed-runtime-resilience.md), and [`fixed-authority-model-formalization.md`](fixed-authority-model-formalization.md).

Not triggered by a `gap-*.md` finding from the 2026-08-24 audit — `findings.md` never flagged missing observability as a gap (it wasn't in the original audit brief's scope). This was project-owner-directed new work, going through `EnterPlanMode` given the real architectural decisions involved (logging library, metrics library, correlation-identity shape) — confirmed with the project owner: draft `observability.md` and implement in one pass, Prometheus `client_golang` behind a CompanyOS-owned port rather than the full OpenTelemetry SDK.

## What was found (establishing current state, before any change)

A targeted research pass (not a full re-audit) confirmed, with file:line citations:

- `apps/companyd` logged exclusively via stdlib `log.Print*`/`log.Printf`/`log.Println`, string-interpolated, zero structured (key-value) fields anywhere — self-documented as a known gap in `cmd/companyd/main.go`'s own boot-stage-3 comment and `docs/adr/ADR-0006-daemon-boot-sequence.md`'s open question.
- No metrics library, hand-rolled counter, or `/metrics` endpoint existed anywhere (`grep` for `prometheus`/`client_golang`/`expvar`/`opentelemetry`/`statsd` across `apps/companyd`: zero hits outside this change).
- `GET /health` (`internal/adapters/httpapi/health.go`) checked only process liveness and one DB ping — no Runtime/sweeper/lease-backlog visibility.
- No correlation ID was ever threaded through `context.Context` — the only two `context.WithValue` call sites in the whole module were `httpapi/auth.go` (attached `AuthenticatedEvidence`) and `httpapi/principal.go` (attached the resolved `Principal`). `CorrelationID`/`CausationID` already existed as **struct fields** on `command.WorkflowCommandEnvelope`, `command.KernelDecisionEnvelope`, `policy.GovernanceDecision`, `event.DomainEvent` — just never surfaced to logs or propagated through context.
- The execution lifecycle this needed to observe was already fully modeled in real Go structs with no gaps to fill in the domain layer itself: `execution.ExecutionAttempt` already carries `AttemptID`, `AttemptNumber` (retry count), `LeaseFencingToken`/`LeaseExpiresAt` (lease state), `Status` (lifecycle state); `result.Result` already carries `ProviderAdapter`, `Outcome`, `ErrorClassification` (failure reason). This work instruments that exact, already-complete mapping — [`fixed-execution-lifecycle-hardening.md`](fixed-execution-lifecycle-hardening.md)'s own lifecycle-stage-to-code table — rather than adding any new domain field.
- Two concrete redaction risks, not confirmed leaks: `internal/adapters/intelligence/fallback/adapter.go` logged a provider's raw `%v`-formatted error on every retryable/terminal failure (could echo a safety-filter/rate-limit message quoting prompt content); `httpapi/auth.go`/`principal.go`'s own doc comments explicitly said the attached `AuthenticatedEvidence`/`Principal` values were "available here for logging" without ever stating what of them was safe to log.
- CI (`.github/workflows/ci.yml`/`nightly.yml`) has no observability-specific gate (no `/metrics` check, no log-format assertion) — nothing to extend or avoid breaking.

## What was implemented

1. **Correlation identity** — new `internal/observability.ExecutionContext` (`context.go`): CorrelationID, CommandID, OrganizationID, WorkflowID, ExecutionIntentID, ExecutionAttemptID, PrincipalID, GovernanceDecisionID/Outcome, Provider, RetryCount, LeaseState, FailureReason, LifecycleState, StartedAt/CompletedAt — every field already existed as a domain field elsewhere (see table in `observability.md`); this type only carries them through `context.Context`. `WithExecutionContext`/`FromContext`/`.With(...)` let each layer (HTTP → Application → Governance → Runtime) progressively enrich the same identity without clobbering fields an earlier layer already set.
2. **Structured logging** — `internal/observability.Init(w, level)` (boot stage 3, `main.go`) configures a process-wide `log/slog` JSON handler (`LOG_LEVEL` env, default `info`) — stdlib since Go 1.21, zero new dependency (`go.mod` already targets 1.25). `observability.Logger(ctx)` returns it enriched with `FromContext(ctx).Attrs()`. Every `log.Print*` call site in `main.go`, `runtime.go`, `application.go`, `sweeper.go`, `fallback/adapter.go`, `httpapi/principal.go` was replaced with a structured call through this logger — confirmed by `grep -rn '"log"$\|log\.Print\|log\.Fatal'` over `apps/companyd`, which now returns only `internal/agent/examples/echo_agent.go` (self-disclaimed dead example code, unreferenced by `cmd`, per `findings.md` §1.0 — out of scope).
3. **Redaction** — `internal/observability.SafeProviderError(err, retryable)` (`redact.go`) truncates a provider error to 200 chars and classifies it (`retryable:`/`terminal:` prefix) instead of logging it verbatim — closes the `fallback/adapter.go` risk found above. `observability.md`'s Redaction section states the full prohibited-field list (raw JWTs, provider API keys/headers, `AuthenticatedEvidence.Subject`/`.Email` unmasked, raw connection-establishment error strings).
4. **Metrics port + adapter** — new `ports.MetricsRecorder` (`ports/metrics.go`): `IncrCounter`/`ObserveHistogram`/`SetGauge`, all label-mapped. Implemented by `internal/adapters/observability/prometheus.Recorder` (`recorder.go`) using `github.com/prometheus/client_golang` (new dependency, `go.mod`) — the only file in the module that imports it. `Recorder` pre-registers a fixed metric vocabulary at construction (never a dynamically-named metric, bounding label cardinality): `governance_decisions_total{outcome,action}`, `executions_total{state}` (state is the exact `execution.AttemptStatus` string — reuses the domain's own bounded enum instead of inventing a second one), `retries_total`, `abandoned_total`, `lease_expirations_total`, `provider_latency_seconds{provider,outcome}`, `approval_latency_seconds`, `outbox_backlog`, `reconciliation_runs_total`. `GET /metrics` mounted unauthenticated (`main.go`), same posture as `/health`.
5. **Governance instrumentation** — new `internal/observability.RecordGovernanceDecision(ctx, metrics, decision)` (`governance.go`), called from all **five** places a `policy.GovernanceDecision` is persisted, immediately after `SaveGovernanceDecision` succeeds (never before — see Non-authority invariant below): `pipeline.go`'s `evaluateGovernance` (Workflow commands), `automatic_governance.go`'s `evaluateAutomaticGovernance` (Research/M&E/Finance), `objective_governance.go`'s `evaluateObjectiveProposalGovernance`, `knowledge_governance.go`'s `evaluateKnowledgeApprovalGovernance`, and `workflow_start.go`'s `AuthorizeDispatch` (the dispatch-time re-evaluation, both its stale-version-deny branch and its normal `governance.Evaluate` branch) — five call sites, not the four `findings.md` §2 enumerated, since `AuthorizeDispatch` persists a decision through the same `SaveGovernanceDecision` method but was never counted as a distinct "governance-evaluation call site" in that audit's language. Sharing one emission helper across these sites is a side-effect-only convenience (the same kind of sharing these call sites already do via `SaveGovernanceDecision` itself), not the domain-control-flow generalization this codebase's own governance wrappers deliberately avoid (`ROADMAP.md` Phase 4 Slice 4, Phase 5 Slice 2's documented non-generalization discipline) — no wrapper's control flow changed, only one new line added after each existing persistence call.
6. **Runtime instrumentation** (`runtime.go`) — every `log.Printf` replaced with a structured `observability.Logger(ctx)` call carrying `ExecutionContext` attrs (new `attemptContext` helper builds it from a claimed `ExecutionAttempt`/`ExecutionIntent`); metrics added at claim (`executions_total{state=CLAIMED}`), lease reclaim (`lease_expirations_total`), retry scheduling (`retries_total`, both the provider-failure and lease-reclaim-retry paths), exhausted-retry termination (`abandoned_total`), around the provider call (`provider_latency_seconds{provider,outcome}`, timed with `time.Since`), and terminal recording (`executions_total{state=<terminal AttemptStatus>}`). All additive to the existing dispatch/retry/reclaim logic — no control-flow change.
7. **Outbox sweeper instrumentation** (`sweeper.go`) — `outbox_backlog` gauge set to the unpublished count loaded each `Sweep`; `reconciliation_runs_total` incremented once per `Sweep`; new `Diagnostics() (backlog int, lastReconcileAt time.Time)` method (atomics, since `health.go`'s HTTP handler reads it from a different goroutine than `Sweep` runs on) backs `/health`'s new diagnostic fields.
8. **`/health` extended** (`health.go`) — new `Diagnostics` interface (`Sweeper` satisfies it); `HealthResponse` gained `outboxBacklog`/`lastReconcileAt` (both `omitempty`, populated only when a sweeper is running) — read-only, side-effect-free, per `docs/architecture/daemon.md`'s "Health probes are side-effect free." `HealthHandler`'s signature changed from `(db)` to `(db, diag)`; `main.go`'s registration moved from immediately-after-boot-stage-4 to immediately-before-boot-stage-10 (`ListenAndServe`) so `diag` can reflect whether the boot-stage-8b sweeper actually started — no observable behavior change, since no route is reachable until `ListenAndServe` regardless.
9. **HTTP-layer correlation seeding** — new `httpapi.WithObservability` middleware (`observability.go`) seeds a fresh `CorrelationID` on every request before `RequireHumanAuth`/`ResolvePrincipal` run (so even a `401` is logged with one); `ResolvePrincipal` (`principal.go`) enriches the same context with the resolved `PrincipalID`/`OrganizationID` once known. Wired into every `/v1/...` route's `withAuth` composition in `main.go`.
10. **One real latent bug found and fixed along the way**: `PendingCommandRepository.ResolveApproval` (`pending_repo.go`) wrote `decided_at=now()` to the database but never set the corresponding `appr.DecidedAt` field on the Go struct it returned — the approval-latency histogram this work adds would have silently never fired. Fixed by computing `decidedAt := time.Now().UTC()` once in Go, using it for both the SQL parameter and `appr.DecidedAt = &decidedAt`, so the returned struct and the persisted row are guaranteed identical rather than merely close. Confirmed no fake implementation of this method exists that would mask the same gap (`fake_repo_test.go`'s `fakePending.ResolveApproval` always returns `ports.ErrConflict`, never reaching the success path).

## Non-authority invariant — how it holds

Per `observability.md`'s own invariant and `docs/domain/event.md`'s "logs and telemetry become DomainEvents only through their owning Application/Kernel operation":

- Every metric/log emission added in this work sits **after** the domain write it describes already committed — `RecordGovernanceDecision` is called only after `SaveGovernanceDecision` returns `nil`; Runtime's terminal-state counters fire only after `RecordTerminal`/`SaveResult` succeed; the outbox gauge is set from a value already read from the database, never computed speculatively.
- No new code path reads a log or metric value back to make a domain decision — confirmed by grep: nothing in `internal/application`/`internal/kernel`/`internal/governance` imports `internal/observability` for anything but `Logger`/`RecordGovernanceDecision`/`SafeProviderError` (write-only use).
- A nil `MetricsRecorder`/`Diagnostics` is never an error anywhere it's consumed (`Runtime.incrCounter`/`observeHistogram`, `Application`'s call sites, `health.go`'s `diag != nil` check) — the same nil-safe pattern `ports.ChangeNotifier`/`Notifier` already established, so observability can be silently absent without breaking any governed path.
