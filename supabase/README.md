# Supabase project

This is the [Supabase CLI](https://supabase.com/docs/guides/cli) project root for CompanyOS.

The CLI itself is not installed globally — it's a local dev dependency at the repo root
(`package.json` → `devDependencies.supabase`), run via `npx supabase ...` from this directory.
Supabase does not support `npm install -g supabase`; the local-devDependency + `npx` pattern is
their documented alternative on platforms without Scoop/Homebrew (this machine has neither).

- The project is **not yet linked** to the hosted project (`ayzzfrvslcwqlxtwvpax`). Run
  `npx supabase login` then `npx supabase link --project-ref ayzzfrvslcwqlxtwvpax` from this
  directory to link it.
- `migrations/` is empty. No schema exists yet, hosted or local.

## Commands

Run from this directory (`supabase/`), with `npx` in front of each:

- `supabase login` — one-time browser auth, needed before `link` or `db push`
- `supabase link --project-ref ayzzfrvslcwqlxtwvpax` — connect this CLI project to the hosted one
- `supabase migration new <name>` — scaffold a new migration file under `migrations/`
- `supabase db push` — apply local migrations to the linked hosted project
- `supabase db pull` — pull the hosted schema down as a migration (useful if the dashboard is
  ever used to make schema changes directly, which should otherwise be avoided — migrations are
  the source of truth)

## Secrets

None of the values needed to actually connect (`service_role` key, direct Postgres connection
string) belong in this directory or anywhere tracked by git. They go in `apps/companyd/.env`
(gitignored), never in `config.toml` or a migration file.
